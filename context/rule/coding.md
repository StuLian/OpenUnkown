# AI 编码约束（每次写代码前必读）

> 本文件是「写代码」这一动作的硬约束。任何写代码动作开始前，必须先读本文件并遵守。
> 触发时机由 `AGENTS.md` 第 6 节「AI 开发纪律」路由表定义。

## 一、铁律（最高优先级，任何情况下不可跳过）

1. **非轻量变更，先出 proposal 获人确认，未获批不写代码**（模板见 `proposal.md`）。
2. **修 bug 前必须先做历史回溯**：grep `context/risk-ledger.md` 定位 + 读对应 `version/` 记录。
3. **写完代码必须走收尾流程**（见 `change_sop.md`）。

## 二、六条硬约束

### 1. 架构设计先行
动手前先想清楚模块边界、数据流、错误处理，把方案写进 proposal 的「方案」节。
禁止「边写边想」，禁止把不相关逻辑塞进一个文件。

### 2. 目录结构符合约定
- 后端代码放 `backend/<domain>/`，路由在 `api/routers/`，存取在 `store/`；
- 新模块须同步更新 `AGENTS.md` 第 3 节「模块职责」（手写区）；
- 不随意新建顶层目录；确需新建时在 proposal 里说明理由。

### 3. 每个文件不超过 300 行
- 超过 300 行必须拆模块/拆函数，禁止无限增长；
- 存量文件已超限时，本次改动不得再增加行数（可拆出子模块降低）。
- **拆分必须成「包」（2026-09-19 补充）**：当一个功能模块超过 300 行需要拆分时，
  **禁止**把拆出的子文件平铺到上级目录，必须为该模块建立**同名文件夹**，把子模块收进去，
  保证拆分后仍是一个内聚、边界清晰的模块单元。
  - 后端 Python：`x/foo.py` 超限 → 目录 `x/foo/` + `__init__.py`（对外导出保持不变，调用方 `from x.foo import ...` 无需改）+ `x/foo/<子职责>.py`；
  - 前端 TS：`components/Foo.tsx` 超限 → 目录 `components/Foo/` + `index.tsx` 作为入口 + 同目录子组件；
  - 测试：`test/test_foo.py` 超限 → 目录 `test/foo/` 收纳同模块的多个测试文件。
  - **反例**：把 `SettingsModal.tsx` 拆成平级的 `SettingsModal.tsx` + `MemorySection.tsx`（散落在 `components/`）——应改为 `components/Settings/{index.tsx,MemorySection.tsx}`。
- **豁免（2026-09-19 人工裁定）**：纯样式文件（如 `frontend/src/styles.css`）**不受本约束**——
  CSS 无逻辑分支、体量随功能线性增长，强行拆分反而增加查找与维护成本。

### 4. 输出的代码要有依据
- 不存在的 API / 方法 / 参数**禁止凭记忆编造**；
- 依据来源必须可查：官方文档、库源码、本仓库既有模式、真实执行结果；
- 引用的依据在 proposal「依据」节注明来源，供人抽查。

### 5. 推理生成的代码要标注【推理生成】
- 凡不是「从依据直接得出」、而是模型自行推导/猜测的代码，在**代码注释**里标注 `【推理生成】`；
- 标注了【推理生成】的代码 = 置信度较低，收尾验证时默认纳入黄灯检查项。

### 6. 一个提交对应一个变更目录（2026-09-20 补充）
- `context/version/<变更ID>/` 的边界是「**一次提交 / 一个功能批次**」，不是「每个中间动作」；
- 同一个未提交工作区内、围绕同一功能的连续迭代（人工追加的小需求、验证后的修复、结构回改、样式微调），
  一律**追加到同一目录的 feature.md / test_report.md**，禁止新开目录；
- 只有当改动形成一个**可独立提交的新功能**时，才新建变更 ID 与目录。
- **目录内固定 4 份文档**：每个变更目录只含 `proposal.md` / `feature.md` / `test_plan.md` / `test_report.md`
  各一份（轻量变更可只含 `feature.md`）；子功能的提案 / 计划 / 报告一律**合并进对应文档**，
  禁止用 `proposal_xxx.md` / `test_report_xxx.md` 之类后缀并列多份。

## 三、测试重点

- 改动涉及逻辑/算法 → 必须补至少 1 条对应测试；
- 改动涉及接口/路由 → 必须验证 import + 类型检查 + 相关用例；
- 改动涉及安全/加密/DB → 额外人工审查项（见 `review.md`）。
