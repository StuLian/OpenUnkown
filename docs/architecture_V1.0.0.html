1项目概览

OpenUnknown 是一个以 LangGraph 为 Agent 框架搭建的 Web 侧问答系统。当前版本聚焦于多轮对话问答，提供流式输出、多会话管理与历史持久化能力，后续可在同一图结构上扩展工具调用、检索增强等能力。

4.2 整体分层

系统分为三层：前端单页、FastAPI 服务层、LangGraph Agent 层。前端与后端同源部署，通过 SSE 接收流式回答。

浏览器 (index.html) --HTTP/SSE--> FastAPI (main.py) --astream--> LangGraph (graph.py) --ainvoke--> qwen-max (DashScope)

4.3 LangGraph 图结构

当前图基于 ReAct 循环架构：包含 chat 与 tools 两个核心节点。当模型需要调用内置工具或 MCP 扩展工具时路由到 tools 节点执行，再回到 chat 进行自然语言回复；若无需调用工具则直接结束。checkpointer 为 AsyncSqliteSaver，按 thread_id（即 session_id）隔离多轮上下文。

5流式输出是怎么做的

采用 SSE（Server-Sent Events）而非 WebSocket，因为问答只需服务端单向推送，SSE 基于普通 HTTP、实现更轻，且配合 LangGraph 的 stream_mode="messages" 天然就是 token 级增量。

5.1 时序图

sequenceDiagram
    autonumber
    participant U as 浏览器 (app.js)
    participant F as FastAPI (main.py)
    participant G as LangGraph (graph.py)
    participant M as qwen-max

    U->>F: POST /api/chat { message, session_id }
    F->>G: graph.astream(stream_mode="messages")
    G->>M: await llm.ainvoke(messages)
    loop 每个 token 增量
        M-->>G: token chunk
        G-->>F: (chunk, meta)
        F-->>U: data: {"delta": "..."}
        U->>U: 累加渲染(打字机效果)
    end
    F-->>U: data: {"usage": {...}}
    F-->>U: data: [DONE]

5.2 关键实现点

  • 后端 graph.astream(stream_mode="messages") 逐 token 产出增量，只保留 chat 节点的内容。
  • 每个增量打包为 data: {"delta": "..."}\n\n 的 SSE 消息，用 StreamingResponse(media_type="text/event-stream") 持续写入连接。
  • 前端用 resp.body.getReader() 循环读取字节流，按 \n 拆行解析；用 buffer 处理跨分片的“半行”问题。
  • 每读到一个 delta 就累加到气泡文本，实现打字机效果。
  • 结束前回传 {"usage": {...}} token 用量，最后发 data: [DONE] 收尾。

5.3 中断机制

前端用 AbortController 中断 fetch；后端在每个 chunk 前检查 request.is_disconnected()，客户端断开即 break，async 生成器关闭会真正取消底层 qwen-max 请求，避免空跑浪费 token。

6核心模块

6.1 backend/config.py

集中配置：模型名 qwen-max、DashScope OpenAI 兼容 BaseURL、应用名。get_api_key() 调用 get_default_api_key 获取密钥并缓存。

6.2 backend/agent/llm.py

封装 ChatOpenAI，指向 DashScope 兼容端点，开启 streaming 与 stream_usage。

6.3 backend/agent/graph.py

定义系统提示词（含模型身份）、_chat_node 异步节点、get_graph() 构建并编译图。checkpointer 为 AsyncSqliteSaver，数据库位于 data/openunknown.db。

6.4 backend/store.py

会话元数据 CRUD：维护 sessions(id, title, created_at, updated_at) 表，标题取首条消息前 24 字。删除会话时同步清理 checkpoint 表数据。

6.5 backend/main.py

FastAPI 入口：挂载 /static、首页返回 index.html、/api/chat 流式问答、会话管理接口。

6.6 frontend

原生单页：侧边栏会话列表（新建/切换/删除）、主区流式对话、localStorage 记住当前会话、刷新自动恢复。

8持久化是怎么做的

所有持久化数据集中存于 data/openunknown.db（SQLite，开启 WAL 模式），由两套逻辑共用同一个数据库文件管理，以 session_id 作为贯穿两者的关联键。

8.1 两类数据

数据管理者数据表作用
对话状态AsyncSqliteSavercheckpoints / writes完整多轮对话状态，支持恢复上下文
会话元数据store.pysessions标题与时间戳，用于侧边栏列表与排序

8.3 关键点

  • thread_id = session_id：checkpoint 以 thread_id 隔离会话，与元数据表的 id 一一对应。
  • 首条消息自动建会话：/api/chat 收到消息时 create_session（已存在则忽略），标题取首条消息前 24 字。
  • 异步 checkpointer：AsyncSqliteSaver 配合 aiosqlite，与节点的 ainvoke、接口的 astream 全链路异步。
  • 删除级联：删除会话时同时清理 sessions 与 checkpoint 表中对应 thread_id 的数据。
服务重启后历史对话完整保留；如需生产级部署，可将 AsyncSqliteSaver 替换为 AsyncPostgresSaver，接口与图结构均无需改动。

9启动方式

# 安装依赖
pip install -r requirements.txt

# 启动服务
uvicorn backend.main:app --host 127.0.0.1 --port 8000

# 开发模式(代码变更自动重载)
uvicorn backend.main:app --host 127.0.0.1 --port 8000 --reload

启动后访问 http://127.0.0.1:8000 即可使用。

10关键设计决策

  • SSE 而非 WebSocket：问答为单向推送场景，SSE 更轻量、契合 LangGraph stream_mode 天然增量。
  • 同源部署：前端由同一 FastAPI 服务返回，前端用相对路径调接口，无需跨域配置。
  • session_id 由前端生成：首条消息时后端自动创建会话元数据，标题取首条消息，省去预创建空会话的往返。
  • 异步贯穿：节点 ainvoke + astream + AsyncSqliteSaver，保证客户端断开可真正中断底层请求。
  • 消除 fallback 思路：ApiKey 统一从 get_default_api_key 读取，未配置即显式报错，不堆叠兜底逻辑。
